## 必查項目

### 寫入阻擋能否被繞過

- **結論：** 以目前的白名單來看，無法繞過。

- **理由：**

  - 外掛判斷的是「白名單裡的 SQL」，不是瀏覽器送來的文字。瀏覽器只能選名稱，所以沒辦法偽裝成讀取。

  - 白名單裡的 11 個寫入查詢，開頭都是 INSERT 或 UPDATE（`mastery.upsertLeitner` 雖然含 `ON CONFLICT ... DO UPDATE`，開頭仍是 INSERT）。正規表示式的 `^\s*` 有處理多行字串開頭的換行和空白。

  - 外掛和 `api/query.js` 拿到的是同一個 `body` 物件，兩邊不會解讀成不同的查詢。唯一的差別是 `params: null`：外掛當成空陣列，handler 當成 `null`；但這時寫入查詢在兩邊都會因參數數量不符而回傳 400，不會被執行。

  - 沒有任何寫入查詢的參數是 0 個，所以「外掛判斷失敗、handler 卻成功」的組合不存在。

### 是否會進入正式建置或 Vercel 部署

- **不會進入正式建置：** `apply: 'serve'` 讓 Vite 只在開發伺服器載入這個外掛；`npm run build` 和 `vite preview` 都不會執行 `configureServer`。

- **不會變成 Vercel 端點：** Vercel 只把 `api/` 底下的檔案當成伺服器端點，`dev/` 不在其中。`vite.config.js` 在建置時仍會載入這個檔案並讀取 `.env`，但只是建立外掛設定，不會啟動任何東西。

- **正式站的處理方式不變：** 正式站仍由 `api/query.js` 處理，那裡沒有寫入阻擋，測驗頁在正式站照常寫入（INV-3）。

### 環境變數處理是否會洩漏

- **這次修改不會洩漏：** 憑證只複製到開發伺服器自己的 `process.env`，不會出現在回應或網頁程式裡。`.env` 已經被 `.gitignore` 排除（第 29 行），不會被提交。

- **原本就有的風險（建議）：** `.env` 裡的資料庫憑證用 `VITE_` 開頭（`VITE_TURSO_AUTH_TOKEN`）。Vite 會把 `VITE_` 開頭的變數視為「可以給瀏覽器看」。開發模式下，只要某個模組用到 `import.meta.env`（例如 `src/main.jsx`、`src/config/turso-api.js`），瀏覽器就可能收到全部 `VITE_` 變數，包括這個憑證。正式建置只會換入程式實際用到的變數，目前沒有用到它，所以正式站不受影響。外掛已經支援 `TURSO_HTTP_URL`、`TURSO_AUTH_TOKEN`，建議把 `.env` 的變數改成不帶 `VITE_` 的名稱。

### S-1（建議）測驗頁在本機預覽預設無法使用，使用者可能誤以為壞了

- **檔案與行號：** `dev/api-dev-plugin.js` 第 32–34 行；`src/pages/QuizPage.jsx` 第 64–80 行。

- **觸發情境：** 用 `npm run dev` 預覽，進入測驗頁按「開始測驗」。

- **影響：** `quiz.createSession` 被回傳 403，測驗頁跳出「測驗啟動失敗，請稍後再試」。使用者是要「確認後再部署」，可能因此誤判測驗頁壞了。

### S-2（建議）請求內容是 `null` 或伺服器端出錯時，外掛的程式沒有接住錯誤

- **檔案與行號：** `dev/api-dev-plugin.js` 第 17–38 行。

- **觸發情境：** 送出內容是 `null` 的請求（`JSON.parse('null')` 會得到 `null`），接著讀取 `body.name` 時出錯；或是 `ssrLoadModule` 載入 `api/query.js` 失敗。

- **影響：** 這段程式是非同步的，出錯時 Vite 的中介層不會幫忙接住，所以這個請求會一直沒有回應。依照 Node 的預設設定，沒被接住的非同步錯誤可能讓開發伺服器整個停止。只影響本機預覽，不影響正式站，也不會寫入資料庫。

- **證據：** 第 21 行只在 JSON 解析失敗時回到 `{}`；解析成功但結果是 `null` 時沒有檢查。整段處理也沒有 try/catch。這點是從程式碼推論，沒有實際執行（依指示不啟動伺服器）。

- **建議做法：** 把第 21 行改成只接受物件（不是物件就用 `{}`），並用 try/catch 包住整段處理，出錯時回傳 500。

### S-3（建議）寫入阻擋用「黑名單」比對開頭，日後新增別種寫入時要同步更新

- **檔案與行號：** `dev/api-dev-plugin.js` 第 32 行。

- **影響：** 目前正確。但如果日後白名單加入以 `WITH`、`REPLACE`、`DELETE` 開頭的寫入，本機預覽不會擋下，而會直接寫入正式資料庫。

- **建議做法：** 改成「白名單」寫法：只允許以 `SELECT` 開頭的查詢，其他一律擋下。
